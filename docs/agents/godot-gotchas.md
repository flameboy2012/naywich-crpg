# Godot 4.7 .NET gotchas

Lessons verified on this machine during M1. They cover what the config files and code don't tell you. For the project layout, read the repo itself.

Engine: `E:\files\godot\Godot_v4.7.2-stable_mono_win64_console.exe` (not on PATH). Use the `_console` exe so you get stdout.

## The verify loop

Run these in order from `game/`, every time:

1. `dotnet build ..\Crpg.sln`. Godot cannot find C# classes until they are built ("associated class could not be found"). Prefer this to `--build-solutions`, because it shows real compiler errors.
2. `--headless --path . --import`. Always run this in a fresh clone or worktree, and after adding PNGs or `.cs` files. `dotnet build` creates `.godot/` without importing assets. New `.cs.uid` files only appear on import; commit them.
3. `--headless --path . --fixed-fps 60 --quit-after N`. With `--fixed-fps 60`, N frames is N/60 seconds of game time, so results are repeatable.
4. Grep the output for `ERROR:`. Godot exits 0 even when scripts throw, so the exit code proves nothing. Only the check tools' own `Quit(1)` gives a non-zero exit.

Give every `--script` run a `--quit-after`. A tool that throws before `Quit()` hangs forever.

A check that runs out of frames is stopped by `--quit-after` and exits 0 without printing its PASSED line. Run each check with the `--quit-after` documented in its file, and treat a missing `<Check>: PASSED` line as a failure, whatever the exit code.

## Headless checks

Engine-level checks live in `game/tools/*Check.cs` and share `HeadlessCheck.cs`. They push real mouse input through the viewport and fail with a non-zero exit. Run each one with `--script res://tools/<Name>.cs` and a generous `--quit-after` (the doc comment in each file gives the command). Keep all of them passing, and add one for each new engine behaviour.

Input in checks:

- **`Root.PushInput` doesn't update the `Input` singleton.** Code that polls held keys (`Input.GetAxis`, `Input.IsKeyPressed`) sees nothing. Use `Input.ParseInputEvent` for held keys; it still reaches `_UnhandledInput`.
- **Key releases arrive a frame late.** Wait a couple of frames after a release before measuring.
- **Measure the camera rig's `GlobalPosition`.** `Camera2D.GetScreenCenterPosition()` lags a frame.
- **The headless mouse sits at (0,0) in a focused window.** Edge pan would keep panning to the top-left, so it is off when the display server is `headless`. Edge pan can only be play-tested. The window's `MouseEntered` signal also fires for input the checks push, so it can't tell whether the real mouse is inside.
- **A check can pass without the bug.** A release over a portrait reached `_UnhandledInput` headlessly even when the real mouse would not. Make each new case fail first; if it can't, put the case on the play-test list.

The zone and art are generated by `game/tools/BuildTestZone.cs` and `GenArt.cs`. Change those tools and rerun them; don't hand-edit the generated `.tscn`, `.tres` or PNGs. A rerun changes random `unique_id` values in `TestZone.tscn`. Revert those if nothing else changed.

## Navigation

- **Map sync lag.** For several frames after a zone loads, `NavigationServer2D.MapGetClosestPoint` and `MapGetPath` return (0,0) or empty, even once `MapGetIterationId > 0`. A check that asserts "closest point differs from the input" then passes without testing anything. Wait until a known ground point maps to itself before asserting.
- **Baking needs outlines.** Tile navigation polygons need `outlines`, not just `polygons`, or the `NavigationRegion2D` bake gives 0 polygons.
- **Layout.** The zone is `NavigationRegion2D > TileMapLayer`, with `NavigationEnabled = false` on the layer. Obstacle tiles carve holes through their collision polygons.
- **Agent distances.** The `NavigationAgent2D` default distances stop well short of the target. The project uses 4 px.

## Physics and input

- A point query on an obstacle tile hits the TileMapLayer, which is a static body. Clicks therefore query only the characters' click areas, which have their own physics layer. Check the layer constants in the code before adding new clickable things.
- **Physics layers.** 1: obstacle tiles. 2: character bodies. 3: party members' click areas. 4: living enemies' click areas (a dead enemy's is cleared). The click layer constants live on `Character`; `AiControl` marks a character as an enemy before it is ready.
- **Control components.** `Character.tscn` has no control component. Party members get `PlayerControl` in `Main.tscn`; enemies get `AiControl` from `BuildTestZone`, which also places them. Rerun it to move or add enemies.
- **Goblins wake.** `AiControl` attacks any party member within a goblin's awareness radius (8 tiles). Once aware, a goblin stays aware until dead and chases the nearest party member still up at any distance, so one stray step wakes it for the rest of the run. Keep the goblin cluster more than that from everywhere the checks walk. A check that needs goblins to stand still sets each `AiControl`'s `ProcessMode` to `Disabled`, as CombatCheck does.
- Godot's `MouseButton` clashes with any Core type of the same name. Use an alias if needed.
- **Loose modifier matching.** By default an action matches whatever modifiers are held, so `pan_left` (A) also fires on Ctrl+A, and `select_slot_1` also fires on Shift+1 and Ctrl+1. When a modifier changes the meaning, read it from the key event and reject the ones you don't want.
- **Drags that cross the UI.** A Control that stops the mouse swallows motion and button releases over it, so a world drag that crosses a portrait stalls or never ends. Read a drag's motion and release in `_Input`, ahead of the UI, and only its press in `_UnhandledInput`.
- **Exported node paths.** An `[Export]` property of a node type needs `node_paths=PackedStringArray("Name", ...)` on its node line in the `.tscn`, as well as the `Name = NodePath(...)` line. Without it the property stays null and nothing reports it until the first use throws.

## Files and git

- **No BOM.** A `.tscn` with a UTF-8 BOM fails to parse (`Expected '['`). PowerShell 5.1 `Set-Content`/`Out-File -Encoding utf8` and `dotnet new sln` all write a BOM. Use the Write tool, or `[IO.File]::WriteAllText(path, text, (New-Object Text.UTF8Encoding $false))`.
- **The editor rewrites `project.godot`.** The first time the project opens in the editor, Godot rewrites the file's header. Commit that before switching branches, or the checkout fails.
- **SDK 10 defaults.** `dotnet new sln` makes `.slnx` unless you pass `--format sln`. `dotnet new` rejects `-f net8.0`, so set `<TargetFramework>net8.0</TargetFramework>` by hand. Every project targets net8.0.
- **Use git 2.56.** An older git (2.15) is also installed, and VS Code's default terminal picked it up during M1. If `git worktree remove`, `git branch --show-current` or agent worktree isolation fail, run `git --version` and switch to a shell that finds 2.56.
- **Line endings.** `.cs` files are LF. A PowerShell replace that searches for CRLF silently does nothing.
- **Worktree paths.** In a worktree, pass absolute paths to .NET file APIs, because relative paths can resolve against the main checkout.
